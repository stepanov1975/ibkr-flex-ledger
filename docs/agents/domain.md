# Domain docs

Use a single-context layout:
- `GLOSSARY.md` at the repository root.
- Architecture decision records under `docs/adr/`.

Before domain exploration, read the glossary and relevant ADRs
when they exist. Proceed silently when absent; domain-modeling
creates them as terms and decisions are resolved.

Use the glossary's vocabulary in proposals, issues, and code.
Surface conflicts with existing ADRs explicitly.

Follow `docs/README.md` for documentation ownership and current
guides. Historical decisions do not define current scope.
Read `docs/technical_reference.md` before changing application code.
